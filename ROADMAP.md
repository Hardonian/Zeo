# Roadmap

This roadmap describes current direction with explicit uncertainty. Timelines can shift based on contributor capacity, security findings, or ecosystem feedback.

## Near-term priorities

### 1) CLI clarity and operator ergonomics

- Improve command discoverability and help consistency.
- Standardize actionable error messages across subcommands.
- Keep deterministic and verification workflows easy to run locally.

### 2) Module ecosystem foundations

- Strengthen module developer onboarding and validation tooling.
- Clarify signature, revocation, and compatibility expectations.
- Expand reference examples for secure, least-privilege modules.

### 3) Provenance and reproducibility hardening

- Improve evidence and export verification experiences.
- Reduce ambiguity in artifact lineage and replay diagnostics.
- Strengthen confidence-range and sensitivity reporting patterns.

## Mid-term direction

### 4) Marketplace and policy-pack interoperability

- Expand trusted module distribution patterns without requiring a centralized control plane.
- Improve pack/module composition checks for deterministic pipelines.
- Preserve adapter boundaries so ecosystem growth does not couple core to one vendor.

### 5) OSS contributor experience

- Better starter templates and docs for first-time contributors.
- Faster local verification loops.
- Clear governance and release communication.

## Non-goals (for now)

- Promising fixed delivery dates for major platform shifts.
- Committing to a single hosted marketplace model.
- Introducing opaque, non-verifiable automation in core decision paths.

## What would change priorities

- Critical security findings.
- Breaking dependency ecosystem changes.
- Strong contributor demand around a specific workflow pain point.
